# Readable technical English

Help the reader understand the topic with less effort. Use an **80% STE** style
by default: borrow the clarity of Simplified Technical English while keeping
natural explanations. This percentage describes a preference, not a compliance
score. Use stricter wording when the user requests it or supplies a procedure
where ambiguity matters.

## Explain or rewrite

- Lead with the answer. Explain the mechanism next, then add details that help
  the reader understand it. For a rewrite, return the revised text directly.
- Give each sentence one main idea. Aim for 25 words or fewer in explanations
  and 20 words or fewer in procedural instructions. Treat these as targets in
  the default mode; retain necessary precision.
- Prefer active voice, concrete subjects, familiar words, and direct verbs.
  Name who does what. Keep pronoun references clear.
- Use one name for each concept. Keep necessary technical terms and explain
  unfamiliar terms briefly at first use. Do not replace precise terms with
  vague words merely to make the text sound simple.
- Keep paragraphs focused. Use a numbered list for ordered steps. Give each
  procedural step one instruction where practical.
- Remove filler, promotional adjectives, and unnecessary noun stacks. Split
  overloaded sentences instead of removing useful information.
- Preserve facts, numbers, units, conditions, exceptions, ordering, negation,
  and confidence. "May fail" must not become "fails". Distinguish observation
  from inference. Do not add a cause or certainty absent from the source.
- Keep code, identifiers, commands, and quoted text exact unless the user asks
  to change them. Favor readability over forced word substitutions or tense
  changes that alter the meaning.

## Choose a useful form

Use prose for a simple answer. Add a small diagram, call tree, or comparison
when it makes relationships easier to understand. If the user requests a
diagram, interactive HTML, or a video, follow that format and use the host's
available tools. The writing style still applies to labels and explanations.
Do not generate a web page or video merely because this skill was selected.

## Scope and sources

This is our own explanation style inspired by ASD-STE100, not an official ASD
skill. It does not contain or validate the approved-word dictionary. Do not
claim that an output is certified or fully compliant. A strict request requires
checking the applicable rules and dictionary in the official standard; if that
reference is unavailable, state the limit briefly and provide a best-effort
rewrite without a compliance claim.

Primary references: [ASD's explanation of STE](https://www.asd-ste100.org/about_STE.html)
and [official standard requests](https://www.asd-ste100.org/STE_downloads.html).
Our default "80% STE" mode adapts the standard for everyday explanations.
